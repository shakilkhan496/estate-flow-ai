Build a production-ready “Role Builder” (no-code RBAC policy editor) INSIDE my app so a SUPER_ADMIN can edit user roles, permissions, scopes, and (optional) field-level rules from the UI without changing code.



CORE PRINCIPLE:
Enforcement logic stays in code, but the RBAC policy (roles/permissions/scopes/field rules) is stored in the database and editable via the Super Admin UI.

--------------------------------------------
DATA MODEL (Prisma)
--------------------------------------------
Create these tables/models:

1) User
- id, email (unique), name, isActive, createdAt, updatedAt

2) Organization
- id, name, type (enum: PLATFORM | ISO | LENDER | MERCHANT), createdAt

3) OrganizationMember  (sub-user logic)
- id, userId, organizationId, roleId, createdAt
- unique(userId, organizationId)

4) Role
- id
- name (string)
- key (string unique, e.g., "ISO_OWNER")
- orgType (enum: PLATFORM | ISO | LENDER | MERCHANT | ANY)
- isSystem (boolean)  // system roles can’t be deleted; can be cloned
- createdAt

5) Permission
- id
- key (string unique, e.g., "SUBMISSION:CREATE")
- description (string)
- group (string, e.g., "Submission", "Offer", "Deal", "Admin")

6) RolePermission
- id
- roleId
- permissionId
- scope (enum: OWN | ASSIGNED | TEAM | ORG | GLOBAL)
- allowed (boolean)
- unique(roleId, permissionId)

7) FieldRule (optional but included)
- id
- roleId
- resource (string, e.g., "Submission", "Deal")
- field (string, e.g., "commissionSplit")
- access (enum: READONLY | HIDDEN | EDITABLE)
- unique(roleId, resource, field)

8) PolicyVersion
- id
- organizationId (nullable for platform-global defaults)
- status (enum: DRAFT | PUBLISHED | ARCHIVED)
- versionNumber (int)
- publishedAt (nullable)
- createdByUserId
- createdAt

9) PolicySnapshot
- id
- policyVersionId
- snapshotJson (jsonb)  // full copy of roles/permissions/field rules for rollback
- createdAt

10) AuditLog
- id
- actorUserId
- organizationId (nullable)
- action (string)
- entityType (string)
- entityId (string)
- metadata (jsonb)
- createdAt

--------------------------------------------
RUNTIME AUTH + ENFORCEMENT
--------------------------------------------
Implement:
1) Active Organization selection (org switcher)
- store activeOrgId in session/token
- API uses activeOrgId to scope access

2) Permission evaluation function:
hasPermission(userId, activeOrgId, permissionKey, resourceContext)
- Loads membership roleId
- Loads RolePermission rows
- Enforces allowed + scope
- Scope logic uses context:
  - OWN: record.createdByUserId == userId
  - ASSIGNED: record.assignedToUserId == userId
  - TEAM: record.teamId matches user team (optional) OR same org with manager relationship
  - ORG: record.organizationId == activeOrgId
  - GLOBAL: platform-level access

3) Field-level enforcement on writes:
applyFieldRules(roleId, resource, incomingData)
- remove/deny fields that are READONLY/HIDDEN
- throw an error if user tries to modify a READONLY/HIDDEN field

4) Middleware:
requireAuth()
requireOrg()
requirePermission("SUBMISSION:EDIT")
All API routes must use middleware, no hardcoded role checks.

--------------------------------------------
SUPER ADMIN UI (OPTION A: INSIDE APP)
--------------------------------------------
Build an admin area gated by permission: ORG:MANAGE_SETTINGS (and SUPER_ADMIN).

Pages:
1) /admin/policy
- Choose Organization (platform or a specific org)
- Shows current policy status (Draft/Published) and version

2) Role Manager
- List roles (filter by orgType)
- Create role (clone from existing recommended)
- Edit role name/key (key immutable after creation)
- Delete role only if isSystem=false and not assigned

3) Permission Matrix Editor
- A table: roles (left) x permissions (top)
- Each cell: toggle allowed/denied
- Each cell: scope dropdown (OWN/ASSIGNED/TEAM/ORG/GLOBAL)
- Search permissions + group by resource

4) Field Rules Editor
- Pick role
- Pick resource (Submission/Deal/Offer)
- Add field rules (field, access)
- Example: Junior broker cannot edit “commissionSplit”, “buyRate”, “lenderRouting”

5) Org Member Manager
- List members in org
- Invite user by email (creates user if not exist)
- Assign role per organization
- Disable member access

6) Policy Versioning
- Draft → Publish workflow
- Publishing creates PolicySnapshot jsonb and increments versionNumber
- Rollback button: restore from snapshot and republish as new version
- Show diff summary (permissions changed count is enough)

--------------------------------------------
GUARDRAILS (MANDATORY)
--------------------------------------------
Implement hard safety rules:
- You cannot remove the last SUPER_ADMIN from the PLATFORM org
- You cannot delete system roles (isSystem=true)
- You cannot publish a policy that leaves org with zero admins (e.g., no role has ORG:MANAGE_USERS)
- Break-glass endpoint protected by an env var token:
  POST /api/admin/break-glass/restore-super-admin
  - reassigns requesting user to SUPER_ADMIN in PLATFORM org
  - logs AuditLog
- Every policy change writes an AuditLog event (who changed what)
